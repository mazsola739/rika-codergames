Every task has its own folder with the write-up, a standalone solution.ts that reads the input file and prints the answer (ready to paste into the submission form), the input and the official answer. npm test runs all of them and compares the output with the official answer. Task 1 · Spain

Claim a spot

Where to open a new stall in the fan zone, and at what price.

Answer1 6

Place the stall, set the price

Move the new stall along the row and change its price. Every kind of fan either never buys from us or has a price ceiling, so revenue rises in a sawtooth and the best price always sits on a ceiling.

Details

At the Grand Prix in a city famous for one architect's style, an unfinished basilica and street blocks with their corners cut off (Barcelona: Gaudí, the Sagrada Família, the Eixample), a row of N stalls sells identical team merchandise. You want to open one more stall: choose where (after existing stall L, never first or last) and at what price P, to maximise the expected revenue.

Fans behave in a fixed way. A fan with patience K walks past exactly K stalls, then goes back to the cheapest one seen. On a tie, they go to the one nearest to where they stopped. Half the fans walk from left to right, half from right to left, and B_K percent of fans have patience K. On equal revenue, the smallest L wins, then the smallest P. The task adds: "brute force is not an option".

Fix the position L and look at one type of fan (direction and K). That fan buys from us exactly when they reach our stall and our price is

  • at most the cheapest price they saw before us (on a tie we were seen later, so we're nearer to where they stop and we win), and
  • strictly below every price they see after us (on a tie, that stall is nearer, so it wins).

So every fan type is either lost, or gives a price ceiling: it buys from us exactly when P ≤ ceiling. As P rises, fans drop out one ceiling at a time, and between two ceilings a higher price only earns more. So the best price is always one of the ceilings. For each L there are at most 2N candidates instead of 9,999 prices. Evaluating each candidate is O(N), which gives O(N³) overall, instant for N ≤ 100.

simulate.ts is the brute force the task warns about, and it's perfect for testing. For every position and every price, it builds the row and walks every fan along it exactly as the story says. It shares no logic with the ceiling argument. check.ts requires the official answer and agreement with the simulation.

For the example (prices 73 418 126 905 200, shares 23 11 49 16 1), the task says the answer is 2 199. But at position 2 nobody can buy at 199. Left-to-right fans pass the 73 first, and right-to-left fans pass the 126 first. Both the program and the brute-force simulation find 4 200: between 905 and 200, right-to-left fans with K = 2 or 3 buy there, for an expected revenue of 60.0. Other readings of the rules (ties always lost, 0-based positions, …) don't produce 2 199 either. For the real input, all of them agree with the official result.

1 6: after the first stall, at price 6. The country is Spain (the Spanish Grand Prix in Barcelona).

// CoderGames 2026, task 1: where to open a merchandise stall in the fan zone, and at what price.
//
// A fan with patience K walks past K stalls, then buys at the cheapest one seen; on a tie, at the
// one nearest to where they stopped, i.e. the one seen LAST. Half the fans walk left to right,
// half right to left, and B[K] percent have patience K. Our stall goes after existing stall L.
//
// For a fixed L, a fan with patience K buys from us exactly when they reach our stall and our
// price P is
//   - at most the lowest price they saw BEFORE our stall (on a tie we were seen later: we win),
//   - and strictly below every price they see AFTER it (on a tie that one is nearer: it wins).
// So every fan type gives a price ceiling (or never buys), and the share of buyers drops in steps
// as P rises. Between two ceilings raising P only earns more, so the best P is always one of the
// ceilings: per L we try at most 2N candidate prices instead of all 9999. O(N^3) overall.
import { readFileSync } from 'node:fs'

const nums = readFileSync(process.argv[2] ?? 'gp.in', 'utf8').trim().split(/\s+/).map(Number)
const n = nums[0]!
const price = nums.slice(1, 1 + n) // price[0..n-1]
const share = nums.slice(1 + n, 1 + 2 * n) // share[K-1] = B_K percent

const minOf = (from: number, to: number) => {
  let m = Infinity
  for (let i = from; i <= to; i++) m = Math.min(m, price[i]!)
  return m
}

// Ceilings for fans walking in one direction. `before` / `after` give the existing stalls a fan
// passes before and after ours (as index ranges), and `seenAt` how many stalls they need to pass
// to reach ours.
interface Fan {
  weight: number // fraction of all fans
  ceiling: number // highest price at which they still buy from us
}

function fansFor(L: number): Fan[] {
  const fans: Fan[] = []
  for (let K = 1; K <= n; K++) {
    const weight = share[K - 1]! / 200 // half of the fans walk each way
    if (weight === 0) continue
    // Left to right: stalls 0..L-1, then ours (the (L+1)-th), then L .. K-2.
    if (K >= L + 1) fans.push({ weight, ceiling: Math.min(minOf(0, L - 1), minOf(L, K - 2) - 1) })
    // Right to left: stalls n-1 .. L, then ours (the (n-L+1)-th), then L-1 down to L-1-(K-(n-L+1))+1.
    const seenAt = n - L + 1
    if (K >= seenAt) fans.push({ weight, ceiling: Math.min(minOf(L, n - 1), minOf(L - (K - seenAt), L - 1) - 1) })
  }
  return fans
}

let best = { revenue: -1, L: 0, P: 0 }
for (let L = 1; L < n; L++) {
  const fans = fansFor(L)
  const candidates = [...new Set(fans.map((f) => f.ceiling))].filter((p) => p >= 1).sort((a, b) => a - b)
  for (const P of candidates) {
    const revenue = P * fans.reduce((s, f) => s + (f.ceiling >= P ? f.weight : 0), 0)
    // Strictly better only: ties keep the smaller L (outer loop) and smaller P (ascending order).
    if (revenue > best.revenue + 1e-9) best = { revenue, L, P }
  }
}
console.log(`${best.L} ${best.P}`)

Task 2 · Germany

The Braille signal

Rebuild a Braille picture from a shuffled telemetry log and read its captions.

Details

An old telemetry archive from a historic racing venue contains 42,320 shuffled records timestamp;row;column;dot;value;status. Together they describe a 110 × 46 raster of 8-dot Braille cells. Rows 0–42 form a picture of a sculpture from the venue's northern curve. Rows 43–45 hold metadata in plain Braille: the location, the people and vehicles shown, and the artist. Only VALID records count; NOISE records are decoys. Print {"country":…, "location":…, "artist":…}. The country isn't written anywhere: work it out from the venue.

  • Ignore the timestamps and the order. Each VALID record says exactly where its dot goes. There are exactly 110 · 46 · 8 = 40,480 of them, one per dot.
  • The dot numbering is Unicode's. Dot 0 is the top-left dot, dots 1–2 go down the left column, 3–5 down the right column, and 6–7 form the bottom row. That's exactly the bit order of the Unicode Braille block, so a cell is the byte Σ value·2^dot, and U+2800 + byte is the character. The whole picture can be printed as text (--image).
  • Read the metadata rows with the standard six-dot Braille alphabet (a = ⠁, b = ⠃, …, plus ⠌ for /).

The three rows read:

avus nordkurve
ewald kluge auf dkw ⠮ ernst jakob henne auf bmw
skulptur von max esser

That's the AVUS, the old race track in Berlin. Its steep north curve is where the picture's sculpture stands: Max Esser's sculpture of the racers Ewald Kluge (on a DKW) and Ernst Jakob Henne (on a BMW). Berlin puts the venue in Germany. That's the one step taken from outside the data, and the program keeps it in a small, clearly marked lookup table.

// CoderGames 2026, task 2: the Braille signal. A shuffled telemetry log holds the dots of a
// 110 x 46 raster of 8-dot Braille cells. Rows 0-42 are a picture, rows 43-45 are metadata in
// plain (uncontracted) Braille: the location, who/what is depicted, and the artist.
//
// 1. Keep only VALID records and set bit `dot` of cell (row, column). The task numbers the dots
//    exactly like the bits of Unicode Braille (U+2800 + bits), so each cell is one character.
// 2. Read the metadata rows letter by letter with the standard Braille alphabet.
// 3. The country is not in the data: the location names a race track, and the track's country
//    is the answer.
// Run with --image to print the picture itself as Unicode Braille.
import { readFileSync } from 'node:fs'

const COLS = 110
const ROWS = 46
const args = process.argv.slice(2)
const file = args.find((a) => !a.startsWith('--')) ?? 'input.txt'
const lines = readFileSync(file, 'utf8').split(/\r?\n/)

const cells = new Uint8Array(ROWS * COLS)
for (const line of lines.slice(1)) {
  const [, row, col, dot, value, status] = line.trim().split(';')
  if (status !== 'VALID' || value !== '1') continue
  cells[Number(row) * COLS + Number(col)]! |= 1 << Number(dot)
}

// Six-dot Braille letters, as Unicode bit masks (dot 1 = bit 0, ..., dot 6 = bit 5).

  [dots(1, 3), 'k'], [dots(1, 2, 3), 'l'], [dots(1, 3, 4), 'm'], [dots(1, 3, 4, 5), 'n'], [dots(1, 3, 5), 'o'],
  [dots(1, 2, 3, 4), 'p'], [dots(1, 2, 3, 4, 5), 'q'], [dots(1, 2, 3, 5), 'r'], [dots(2, 3, 4), 's'],
  [dots(2, 3, 4, 5), 't'], [dots(1, 3, 6), 'u'], [dots(1, 2, 3, 6), 'v'], [dots(2, 4, 5, 6), 'w'],
  [dots(1, 3, 4, 6), 'x'], [dots(1, 3, 4, 5, 6), 'y'], [dots(1, 3, 5, 6), 'z'], [dots(3, 4), '/'], [0, ' '],

// from outside the input: the AVUS is the old race track in Berlin.

Details

A driver's career is a directed acyclic graph of trainings and races. Node 1 is the complete beginner and node N the Formula 1 professional. Count the different paths from 1 to N. Listing paths is hopeless: there are trillions. Counting them is easy with dynamic programming in topological order:

  • ways[1] = 1,
  • every edge a → b adds ways[a] to ways[b],
  • process the nodes in an order where every edge goes forward (Kahn's algorithm: repeatedly take a node with no unprocessed incoming edges), so ways[a] is final before its edges are used.

// CoderGames 2026, task 3: from rookie to Formula 1. Count the paths from node 1 to node N in a
// directed acyclic graph. Process the nodes in topological order (Kahn's algorithm) and push
// path counts forward: ways[1] = 1, and every edge a -> b adds ways[a] to ways[b]. Because the
// graph has no cycles, ways[a] is final before any of its edges are used. O(N + M).
// Counts can exceed 64 bits on bigger graphs, so they are BigInts.
import { readFileSync } from 'node:fs'

const nums = readFileSync(process.argv[2] ?? 'input.txt', 'utf8').trim().split(/\s+/).map(Number)
const [n, m] = nums as [number, number]
const out: number[][] = Array.from({ length: n + 1 }, () => [])
const inDegree = new Int32Array(n + 1)
for (let i = 0; i < m; i++) {
  const a = nums[2 + 2 * i]!
  const b = nums[3 + 2 * i]!
  out[a]!.push(b)
  inDegree[b]!++
}

const ways: bigint[] = new Array(n + 1).fill(0n)
ways[1] = 1n
const queue: number[] = []
for (let v = 1; v <= n; v++) if (inDegree[v] === 0) queue.push(v)
for (let head = 0; head < queue.length; head++) {
  const a = queue[head]!
  for (const b of out[a]!) {
    ways[b] = ways[b]! + ways[a]!
    if (--inDegree[b]! === 0) queue.push(b)
  }
}
console.log(ways[n]!.toString())

Details

Domi may eat only two chocolates, and his dad decides how heavy they must be together. Given a list of chocolate weights and a target, find the indexes of the first two chocolates that add up to the target, or null if no pair does. "First" means the pair whose second chocolate appears earliest: in [1, 2, 3, 4] with target 5, the answer is [1, 2], not [0, 3].

This is the classic two-sum problem. Checking every pair is O(n²). Better: walk through the list once and, for each chocolate j, ask "have I already seen a chocolate weighing target − weight[j]?" A hash map from weight to the first index where it appeared answers that in O(1).

solution.ts · 28 lines of TypeScript. It reads the input file and prints the answer.

// CoderGames 2025, task 1: two chocolates whose weights add up to the target (two-sum).
// "First" means: the pair whose second chocolate comes earliest. So walk left to right and, for
// each chocolate, ask whether its partner (target - weight) was already seen. A map from weight
// to the first index it appeared at answers that in O(1), so the whole scan is O(n).
import { readFileSync } from 'node:fs'

const lines = readFileSync(process.argv[2] ?? 'input.txt', 'utf8')
  .split(/\r?\n/)
  .map((l) => l.trim())
  .filter((l) => l.length > 0)

function firstPair(weights: number[], target: number): [number, number] | null {
  const seen = new Map<number, number>()
  for (let j = 0; j < weights.length; j++) {
    const i = seen.get(target - weights[j]!)
    if (i !== undefined) return [i, j]
    if (!seen.has(weights[j]!)) seen.set(weights[j]!, j)
  }
  return null
}

const out: string[] = []
for (let at = 0; at + 1 < lines.length; at += 2) {
  const weights: number[] = JSON.parse(lines[at]!)
  const pair = firstPair(weights, Number(lines[at + 1]))
  out.push(pair ? `[${pair[0]}, ${pair[1]}]` : 'null')
}
console.log(out.join('\n'))

When edges are only ever added, a union-find (disjoint-set union) is the natural tool. Each set also gets one flag: does this component already contain a cycle?

solution.ts · 51 lines of TypeScript. It reads the input file and prints the answer.

// CoderGames 2025, task 2: corridors only ever appear; after each "?" report how many connected
// components contain a cycle. A union-find (disjoint set union) handles "edges only get added"
// perfectly. Each set also remembers whether it already has a cycle:
// - an edge inside one set closes a cycle: if that set had none, one more cursed component;
// - an edge between two sets merges them: if both were cursed, two cursed components become one.
// With path compression and union by size every event is practically O(1).
import { readFileSync } from 'node:fs'

const lines = readFileSync(process.argv[2] ?? 'input.txt', 'utf8').split(/\r?\n/)
const [n] = lines[0]!.trim().split(/\s+/).map(Number) as [number]

const parent = Int32Array.from({ length: n + 1 }, (_, i) => i)
const size = new Int32Array(n + 1).fill(1)
const cyclic = new Uint8Array(n + 1)
const find = (x: number): number => {
  while (parent[x] !== x) {
    parent[x] = parent[parent[x]!]!
    x = parent[x]!
  }
  return x
}

let cursed = 0
const out: number[] = []
for (const raw of lines.slice(1)) {
  const line = raw.trim()
  if (line === '?') {
    out.push(cursed)
    continue
  }
  const [op, a, b] = line.split(/\s+/)
  if (op !== '+' || a === undefined || b === undefined) continue // blank or broken line
  const u = Number(a)
  const v = Number(b)
  if (u === v) continue // self-loops are ignored, as the task allows
  let ru = find(u)
  let rv = find(v)
  if (ru === rv) {
    if (!cyclic[ru]) {
      cyclic[ru] = 1
      cursed++
    }
    continue
  }
  if (size[ru]! < size[rv]!) [ru, rv] = [rv, ru]
  parent[rv] = ru
  size[ru]! += size[rv]!
  if (cyclic[ru] && cyclic[rv]) cursed--
  cyclic[ru] = cyclic[ru] || cyclic[rv] ? 1 : 0
}
console.log(out.join('\n'))

This is Dijkstra's algorithm on arrival times instead of distances. Normally a road's cost depends on the time you reach it, which breaks shortest-path algorithms. That's the FIFO property, and with it Dijkstra stays correct:

  • take the unfinished station with the earliest arrival time,
  • for each road out of it: departure = the first moment at or after arrival when the road is open, arrival at the other end = departure + travel time,
  • stop when station N is taken (or print −1 if it's unreachable).

The stations are few, so the program uses the simple O(N²) version of Dijkstra without a heap.

What does "closed at your intended time of travel" mean: closed when you set off, or closed at any moment of the ride? The example says the 1 → 2 closure from 110 to 130 "would force a wait" for a ride starting at 100 (arriving at 120). That suggests the whole ride counts. // CoderGames for Women 2025, task 4: the fastest bike route across Valencia during Las Fallas,
// when some roads are closed at certain times and you may wait for them to reopen.
//
// Dijkstra's algorithm on arrival times instead of distances. It still works because waiting is
// allowed: arriving earlier at a station never makes you arrive later anywhere else (the
// "first in, first out" property). A road only has to be open when you set off on it: if you
// reach it during a closure, you wait until the closure ends. (Requiring the whole ride to avoid
// closures gives 105 instead of the official 90 in set 3.)
import { readFileSync } from 'node:fs'

interface Road {
  to: number
  minutes: number
  closed: [number, number][] // [start, end) intervals
}

// Earliest time >= t at which the road is open (closures are [start, end) and may touch).
function departure(t: number, road: Road): number {
  let d = t
  for (let moved = true; moved; ) {
    moved = false
    for (const [s, e] of road.closed) {
      if (s <= d && d < e) {
        d = e
        moved = true
      }
    }
  }
  return d
}

function earliestArrival(n: number, roads: Road[][], start: number): number {
  const best = new Array(n + 1).fill(Infinity)
  best[1] = start
  const done = new Array(n + 1).fill(false)
  for (;;) {
    let u = -1
    for (let v = 1; v <= n; v++) if (!done[v] && best[v] < Infinity && (u < 0 || best[v] < best[u])) u = v
    if (u < 0) break
    if (u === n) return best[n]
    done[u] = true
    for (const road of roads[u]!) {
      const arrive = departure(best[u], road) + road.minutes
      if (arrive < best[road.to]) best[road.to] = arrive
    }
  }
  return -1
}

Details

A security guard at a Mercadona supermarket watches camera feeds in an h × w grid of screen cells. The arrow buttons shift every image one cell left, right, up or down, wrapping around at the edges. Compactness is the area of the smallest rectangle that contains all images. Find the minimum compactness and the fewest button presses that achieve it. Searching all shift combinations is possible, but the task asks for something better.

Two observations make it easy:

  1. Rows and columns are independent. Up/down only changes row numbers, left/right only column numbers, and the area is (rows spanned) × (columns spanned). The minimum area needs both spans to be minimal, so each axis can be solved on its own and the press counts added.
  2. Each axis is a circle. The occupied rows split the circle of h rows into gaps of empty rows. Cut the circle at the largest gap and what remains is the shortest block covering all images: span = h − largest gap.

The block must then end up not wrapping around the screen edge. Its start has to land in 0 … h − span, and the presses needed are the circular distance from its current start to the nearest such position, which is 0 if it already fits. When several gaps tie for largest, take the one needing the fewest presses.

Example: a 3 × 4 grid with images at (1, 1), (3, 4), (1, 4). Rows {1, 3} on a circle of 3: span 2, needs 1 press. Columns {1, 4} on a circle of 4: span 2, needs 1 press. So compactness 4 with 2 presses.

// CoderGames 2024, task 5: CCTV. Camera images sit in an h x w grid; the arrow buttons shift every
// image one cell, wrapping around at the edges. Make the bounding box of all images as small as
// possible, with as few presses as possible.
//
// Up/down only change rows and left/right only change columns, and the box area is
// (rows spanned) x (columns spanned). So rows and columns can be solved separately, each on a
// circle of size h (or w):
// - the occupied rows split the circle into gaps; cutting the circle at the largest gap leaves the
//   shortest block that covers them all: span = h - largest gap;
// - that block has to end up not wrapping around the edge; the presses needed are the circular
//   distance from where it starts to the nearest start that fits. With several largest gaps,
//   take the cheapest one.
import { readFileSync } from 'node:fs'

function solveAxis(positions: number[], size: number): { span: number; moves: number } {
  const occupied = [...new Set(positions)].sort((a, b) => a - b)
  let best = { span: size, moves: 0 }
  if (occupied.length === size) return best
  for (let i = 0; i < occupied.length; i++) {
    // Gap between occupied[i] and the next occupied position going forward around the circle.
    const next = occupied[(i + 1) % occupied.length]!
    const gap = (next - occupied[i]! - 1 + size) % size
    const span = size - gap
    const start = next // the block begins right after this gap
    // Starts that don't wrap: 0 .. size - span. Distance on the circle to the closest of them.
    let moves = Infinity
    for (const t of [0, size - span]) {
      const d = Math.abs(start - t)
      moves = Math.min(moves, d, size - d)
    }
    if (start <= size - span) moves = 0
    if (span < best.span || (span === best.span && moves < best.moves)) best = { span, moves }
  }
  return best
}

// Cases: "h; w; k", then k lines "r; c" (1-based), separated by blank lines.
const numbers = readFileSync(process.argv[2] ?? 'input.txt', 'utf8')
  .split(/\r?\n/)
  .map((l) => l.trim())
  .filter((l) => l.length > 0)
  .map((l) => l.split(/[;\s]+/).map(Number))

const out: string[] = []
for (let at = 0; at < numbers.length; ) {
  const [h, w, k] = numbers[at++]! as [number, number, number]
  const cells = numbers.slice(at, at + k)
  at += k
  const rows = solveAxis(cells.map(([r]) => r! - 1), h)
  const cols = solveAxis(cells.map(([, c]) => c! - 1), w)
  out.push(`${rows.span * cols.span}; ${rows.moves + cols.moves}`)
}
console.log(out.join('\n'))

// a Vigenère cipher: letter i is shifted by the i-th letter of a repeating key. Break it in two
// steps without knowing the key:
//  1. Key length: split the text into k columns (every k-th letter). With the right k each column
//     is plain English shifted by one letter, so its index of coincidence (the chance that two
//     random letters are equal) is close to English's 0.066 instead of random text's 0.038.
//  2. Each column is then a Caesar cipher: try all 26 shifts and keep the one whose letter

import { readFileSync } from 'node:fs'

  const counts = Array(26).fill(0)
  for (const c of letters) counts[c]++
  const n = letters.length

This is the 0/1 knapsack problem. The textbook DP works over integer capacities, but these weights are real numbers like 71.13353423971505, so it doesn't apply directly. Two simpler ideas work very well here:

  1. Greedy by density. Sort the machines by value per unit of weight and take them in that order whenever they still fit. That's instant and already very good.
  2. Branch and bound (the Horowitz–Sahni scheme) turns that into a proven optimum. Explore "take / don't take" decisions in density order, and for every partial choice compute an upper bound: fill the remaining room greedily, allowing a fraction of the first machine that doesn't fit. If that bound can't beat the best packing found so far, the whole branch is skipped. Prefix sums and a binary search make each bound O(log n).

On this input the greedy packing (743,529.61) is already optimal. Branch and bound proves it after visiting only 1,248 search nodes (0.2 s). The fractional bound is just 4.17 higher. Random instances like this are usually easy, which is why the bound is so effective. To be sure the search is right, it was also compared against brute force on 60 small random instances.

// CoderGames 2023, task 5: pack the Mars rocket. 10,000 machines with a usefulness (value) and a
// size (weight, a real number); total size at most 10,000. This is the 0/1 knapsack problem.
//
// The usual DP needs integer weights, and these are floats, so we use branch and bound instead
// (the Horowitz-Sahni scheme):
// - sort the machines by value per unit of weight, best first;
// - the greedy packing (take them in that order while they fit) is a good first answer;
// - for any partial choice, the "fractional" bound (fill the rest greedily, allowing a fraction of
//   the first machine that doesn't fit) is an upper limit on what that choice can still reach,
//   so whole branches that can't beat the best answer so far are skipped.
// Prefix sums plus a binary search make each bound O(log n).
import { readFileSync } from 'node:fs'

interface Item {
  id: number
  value: number
  weight: number
}
const data: { items: Item[]; capacity: number } = JSON.parse(readFileSync(process.argv[2] ?? 'input.json', 'utf8'))
const capacity = data.capacity
const items = data.items.filter((it) => it.weight <= capacity).sort((a, b) => b.value / b.weight - a.value / a.weight)
const n = items.length
const W = new Float64Array(n + 1) // W[i] = weight of items[0..i-1]
const V = new Float64Array(n + 1)
for (let i = 0; i < n; i++) {
  W[i + 1] = W[i]! + items[i]!.weight
  V[i + 1] = V[i]! + items[i]!.value
}
const EPS = 1e-9

// Most value reachable from items i..n-1 with `room` left, allowing one fractional item.
function bound(i: number, room: number): number {
  // largest j >= i with W[j] - W[i] <= room
  let lo = i
  let hi = n
  while (lo < hi) {
    const mid = (lo + hi + 1) >> 1
    if (W[mid]! - W[i]! <= room + EPS) lo = mid
    else hi = mid - 1
  }
  let b = V[lo]! - V[i]!
  if (lo < n) b += ((room - (W[lo]! - W[i]!)) * items[lo]!.value) / items[lo]!.weight
  return b
}

const take = new Uint8Array(n)
let best = -1
let bestTake = new Uint8Array(n)
let value = 0
let room = capacity
let i = 0
let nodes = 0
const deadline = Date.now() + 20_000
let proven = true

search: for (;;) {
  nodes++
  if (i < n && value + bound(i, room) <= best + EPS) {
    // cannot beat the best: backtrack below
  } else {
    // Forward: take items in order while they fit, skip the ones that don't.
    for (; i < n; i++) {
      if (items[i]!.weight <= room + EPS) {
        take[i] = 1
        room -= items[i]!.weight
        value += items[i]!.value
      } else {
        take[i] = 0
        if (value + bound(i + 1, room) <= best + EPS) break
      }
    }
    if (value > best + EPS) {
      // Only take[0..i] belongs to this branch; anything after it is left over from older ones.
      best = value
      bestTake = new Uint8Array(n)
      bestTake.set(take.subarray(0, Math.min(i + 1, n)))
    }
  }
  if ((nodes & 0xffff) === 0 && Date.now() > deadline) {
    proven = false
    break
  }
  // Backtrack: undo the last taken item and try the branch without it.
  let k = Math.min(i, n) - 1
  while (k >= 0 && !take[k]) k--
  if (k < 0) break search
  take[k] = 0
  room += items[k]!.weight
  value -= items[k]!.value
  i = k + 1
}

const chosen = items.filter((_, j) => bestTake[j]).sort((a, b) => a.id - b.id)
const totalWeight = chosen.reduce((s, it) => s + it.weight, 0)
console.log(`Total value: ${best}`)
console.log(`Total weight: ${totalWeight}`)
console.log('items:')
for (const it of chosen) console.log(it.id)
console.error(`${nodes} search nodes, ${proven ? 'optimal' : 'time limit reached, best found'}; upper bound ${bound(0, capacity)}`)

Details

A map is a grid of 1 (land) and 0 (water). An island is a group of land cells connected horizontally or vertically. Connect all islands with bridges, using as little material as possible:

  • a bridge is a straight horizontal or vertical line of 1, 2 or 3 water cells between two islands,
  • every bridge cell costs one unit of material,
  • bridges may cross (the crossing cell costs 2, one for each bridge).

Print the material needed, or -1 if the islands can't all be connected. The input has 103 maps, up to 100 × 100.

Crossings are allowed, so bridges never get in each other's way, and the problem turns into a graph problem:

  1. Find the islands with a flood fill. Each island becomes a node.
  2. List every possible bridge. From each land cell, look right and down: skip 1–3 water cells, and if you land on a different island, that's an edge, weighted by the number of water cells.
  3. Connect everything as cheaply as possible. That's a minimum spanning tree. Kruskal's algorithm sorts the bridges by length and takes each one that joins two not-yet-connected groups, tracked with a union-find. If it ends with more than one group, the answer is -1.

With k candidate bridges this is O(cells + k log k).

My answers matched the official ones on only 10 of the 103 maps. The organisers published their Python solution, and it explains why. Its flood fill checks neighbours like this:

try:
    if neighbour not in map and grid[n_row][n_col] == "1":
        ...
except IndexError:
    pass

The try/except IndexError is meant to catch neighbours outside the map. That works past the bottom and right edges. But above the top edge n_row is -1, and in Python grid[-1] doesn't fail: it's the last row. The same happens with -1 for the left edge. So the flood fill leaves the map through the top or left edge, continues on a "copy" of the bottom or right edge, and can come back in somewhere else. Islands that are far apart get merged, and the result needs fewer bridges than it should.

A 3 × 3 example:

101      three islands: the two top cells and the bottom row
000      correct answer: 2 (two bridges of length 1)
111      official program: 1 (it thinks the two top cells are one island)

To be sure this is the only difference, official.ts is a line-by-line port of the published program with a switch for Python's negative indexing:

  • with Python's behaviour, it reproduces all 103 published answers exactly;
  • without it (-1 treated as outside the map), it agrees with solution.ts on all 103 maps.

// CoderGames 2022, task 5: connect all islands with straight bridges of 1-3 water cells, using as
// little material as possible. Islands are the graph's nodes, every possible bridge is an edge
// weighted by its length, and the cheapest way to connect everything is a minimum spanning tree
// (Kruskal's algorithm with a union-find). Bridges may cross, so they never block each other.
import { readFileSync } from 'node:fs'

const MAX_BRIDGE = 3
const lines = readFileSync(process.argv[2] ?? 'input.txt', 'utf8')
  .split(/\r?\n/)
  .map((l) => l.trim())
  .filter((l) => l.length > 0)

let at = 0
const cases = Number(lines[at++])
const out: number[] = []

for (let t = 0; t < cases; t++) {
  // "N M", then N rows of 0/1 (written with or without spaces).
  const [h, w] = lines[at++]!.split(/\s+/).map(Number) as [number, number]
  const grid = lines.slice(at, at + h).map((row) => row.replace(/\s+/g, ''))
  at += h

  // Label islands with a flood fill.
  const island = new Int32Array(h * w).fill(-1)
  let islands = 0
  for (let start = 0; start < h * w; start++) {
    if (grid[Math.floor(start / w)]![start % w] !== '1' || island[start] !== -1) continue
    const stack = [start]
    island[start] = islands
    while (stack.length) {
      const cell = stack.pop()!
      const r = Math.floor(cell / w)
      const c = cell % w
      for (const [nr, nc] of [[r - 1, c], [r + 1, c], [r, c - 1], [r, c + 1]] as const) {
        if (nr < 0 || nr >= h || nc < 0 || nc >= w || grid[nr]![nc] !== '1') continue
        if (island[nr * w + nc] === -1) {
          island[nr * w + nc] = islands
          stack.push(nr * w + nc)
        }
      }
    }
    islands++
  }

  // Every possible bridge: from a land cell, go right or down over 1-3 water cells to other land.
  const bridges: [length: number, a: number, b: number][] = []
  for (let r = 0; r < h; r++)
    for (let c = 0; c < w; c++) {
      const from = island[r * w + c]!
      if (from === -1) continue
      for (const [dr, dc] of [[0, 1], [1, 0]] as const) {
        for (let len = 1; len <= MAX_BRIDGE + 1; len++) {
          const nr = r + dr * len
          const nc = c + dc * len
          if (nr >= h || nc >= w) break
          const to = island[nr * w + nc]!
          if (to === -1) continue // still water
          if (len > 1 && to !== from) bridges.push([len - 1, from, to])
          break // reached land: either a bridge or our own coast
        }
      }
    }

  // Kruskal: take the shortest bridges first, skip any that join already connected islands.
  const parent = Array.from({ length: islands }, (_, i) => i)
  const root = (x: number): number => (parent[x] === x ? x : (parent[x] = root(parent[x]!)))
  bridges.sort((a, b) => a[0] - b[0])
  let material = 0
  let joined = 0
  for (const [len, a, b] of bridges) {

Details

You're lost in a maze of . (free) and # (rock) cells, starting at S. Find the shortest way to the exit E, moving only up, down, left or right. Print the maze with every . on that path replaced by *, or Trapped if there's no way out. The real maze is 49 × 39.

Breadth-first search (BFS) is the standard tool for shortest paths when every step costs the same. It explores the maze in rings: first the cells 1 step from S, then 2 steps, and so on. So the first time it reaches a cell, it has used the fewest steps possible. If we also remember where we came from for each cell, we can walk back from E to S along a shortest path and mark it.

  • Time: every cell is visited once, so O(rows × columns).
  • Trapped: if BFS runs out of cells without reaching E.

The marked maze in answer.txt. It matches the official solution character for character.

// CoderGames 2021, task 1: shortest way out of a maze. Breadth-first search from S finds the
// shortest path to E; then every '.' on that path is replaced by '*'.
import { readFileSync } from 'node:fs'

const grid = readFileSync(process.argv[2] ?? 'input.txt', 'utf8')
  .split(/\r?\n/)
  .filter((line) => line.length > 0)
  .map((line) => [...line])
const rows = grid.length
const cols = grid[0]!.length

const find = (ch: string): [number, number] => {
  for (let r = 0; r < rows; r++) {
    const c = grid[r]!.indexOf(ch)
    if (c >= 0) return [r, c]
  }
  throw new Error(`no ${ch} in the maze`)
}
const [sr, sc] = find('S')
const [er, ec] = find('E')

// BFS: cells are visited in order of distance from S; `from` remembers how we got to each cell.
const from = new Int32Array(rows * cols).fill(-1)
const queue = [sr * cols + sc]
from[queue[0]!] = queue[0]!
for (let head = 0; head < queue.length; head++) {
  const cell = queue[head]!
  const r = Math.floor(cell / cols)
  const c = cell % cols
  for (const [dr, dc] of [[-1, 0], [1, 0], [0, -1], [0, 1]] as const) {
    const nr = r + dr
    const nc = c + dc
    if (nr < 0 || nr >= rows || nc < 0 || nc >= cols || grid[nr]![nc] === '#') continue
    const next = nr * cols + nc
    if (from[next] !== -1) continue
    from[next] = cell
    queue.push(next)
  }
}

const exit = er * cols + ec
if (from[exit] === -1) console.log('Trapped')
else {
  // Walk back from E to S and mark the path.
  for (let cell = from[exit]!; grid[Math.floor(cell / cols)]![cell % cols] !== 'S'; cell = from[cell]!) {
    grid[Math.floor(cell / cols)]![cell % cols] = '*'
  }
  console.log(grid.map((row) => row.join('')).join('\n'))
}

The program fills best from short blocks to long ones, which is O(n²) states with O(1) work each, and records which end each state chose. Then it replays those choices from the full shelf to print the order.

// CoderGames 2021, task 2: sell one bottle a year, always from one end of the shelf; in year t a
// bottle with price c earns t * c. Interval dynamic programming: best[i][j] is the most we can
// earn from the bottles i..j that are still on the shelf, which also tells us the current year.
import { readFileSync } from 'node:fs'

const lines = readFileSync(process.argv[2] ?? 'input.txt', 'utf8').trim().split(/\r?\n/)
const cases = Number(lines[0])

for (let k = 1; k <= cases; k++) {
  const c = lines[k]!.trim().split(/\s+/).map(Number)
  const n = c.length
  // best[i * n + j]: max earnings for bottles i..j, sold in years n - (j - i), ..., n.
  const best = new Float64Array(n * n)
  const takeLeft = new Uint8Array(n * n)
  for (let len = 1; len <= n; len++) {
    const year = n - len + 1
    for (let i = 0; i + len - 1 < n; i++) {
      const j = i + len - 1
      if (len === 1) {
        best[i * n + j] = year * c[i]!
        takeLeft[i * n + j] = 1
        continue
      }
      const left = year * c[i]! + best[(i + 1) * n + j]!
      const right = year * c[j]! + best[i * n + j - 1]!
      takeLeft[i * n + j] = left >= right ? 1 : 0
      best[i * n + j] = Math.max(left, right)
    }
  }
  // Replay the choices to print the selling order.
  const terms: string[] = []
  for (let i = 0, j = n - 1, year = 1; i <= j; year++) {
    if (takeLeft[i * n + j]) terms.push(`${year}*${c[i++]}`)
    else terms.push(`${year}*${c[j--]}`)
  }
  console.log(`${best[n - 1]}, ${terms.join(' + ')}`)
}

// CoderGames 2021, task 3: shortest distance from every vertex to one target in an unweighted,
// directed graph. One breadth-first search from the target over the reversed edges gives all
// distances at once.
import { readFileSync } from 'node:fs'

const lines = readFileSync(process.argv[2] ?? 'input.txt', 'utf8')
  .split(/\r?\n/)
  .map((l) => l.trim())
  .filter((l) => l.length > 0)

// The cases are pairs of lines: target vertex, then "a,b;c,d;..." edges.
// (The task mentions a count on the first line; the file has none, so we just read pairs.)
const out: string[] = []
for (let i = 0; i + 1 < lines.length; i += 2) {
  const target = lines[i]!
  const reversed = new Map<string, string[]>()
  const vertices = new Set<string>([target])
  for (const edge of lines[i + 1]!.split(';')) {
    if (!edge.trim()) continue
    const [a, b] = edge.split(',').map((v) => v.trim()) as [string, string]
    vertices.add(a).add(b)
    if (!reversed.has(b)) reversed.set(b, [])
    reversed.get(b)!.push(a)
  }

  const dist = new Map<string, number>([[target, 0]])
  const queue = [target]
  for (let head = 0; head < queue.length; head++) {
    const v = queue[head]!
    for (const u of reversed.get(v) ?? []) {
      if (dist.has(u)) continue
      dist.set(u, dist.get(v)! + 1)
      queue.push(u)
    }
  }

  out.push(target)
  // Plain character order, as in the expected output ("10" < "100" < "11" < "a").
  for (const v of [...vertices].sort((a, b) => (a < b ? -1 : a > b ? 1 : 0))) {
    if (v !== target) out.push(`${v} ${dist.get(v) ?? 'INF'}`)
  }
}

// CoderGames 2021, task 4: pay an amount with as few coins as possible (coin change).
// Greedy fails for odd coin systems (30 with 25, 10, 1: greedy pays 25 + 5x1 = 6 coins, the best
// is 3x10), so we use dynamic programming over every amount from 0 to X.
import { readFileSync } from 'node:fs'

const lines = readFileSync(process.argv[2] ?? 'input.txt', 'utf8').trim().split(/\r?\n/)
const cases = Number(lines[0])
const out: string[] = []

for (let k = 0; k < cases; k++) {
  const amount = Number(lines[1 + 2 * k])
  const coins = lines[2 + 2 * k]!.trim().split(/\s+/).map(Number)

  // fewest[x]: fewest coins that make x; last[x]: index of the coin used last for that.
  const fewest = new Int32Array(amount + 1).fill(0x7fffffff)
  const last = new Int8Array(amount + 1).fill(-1)
  fewest[0] = 0
  for (let x = 1; x <= amount; x++) {
    for (let i = 0; i < coins.length; i++) {
      const coin = coins[i]!
      if (coin > x || fewest[x - coin] === 0x7fffffff) continue
      if (fewest[x - coin]! + 1 < fewest[x]!) {
        fewest[x] = fewest[x - coin]! + 1
        last[x] = i
      }
    }
  }

  out.push(String(amount))
  if (fewest[amount] === 0x7fffffff) {
    out.push('INF')
    continue
  }
  const used = coins.map(() => 0)
  for (let x = amount; x > 0; x -= coins[last[x]!]!) used[last[x]!]!++
  out.push(String(fewest[amount]))
  coins.forEach((coin, i) => used[i] && out.push(`${coin}: ${used[i]}`))
}

// CoderGames 2020, task 1: which number is Michal thinking of?

// Letter pairs that look English, plus a bonus for every real word.
function score(key: Key): number {

  for (const { codes, n } of wordCodes) {
    let prev = 26

    let ws = 0
    for (const c of codes) {
      const p = key[c]!
      ws += pairScore[prev * B + p]!
      plain += ALPHABET[p]
      prev = p
    }
    ws += pairScore[prev * B + 26]!

}

// Swap the plain letters behind two cipher letters as long as some swap improves the score.

          improved = true

      }
  }

}

Details

In a dream, Miloš downloads tomorrow's Apple share price for every tenth of a second. He may place one buy order and one later sell order. Comparing every pair of prices (around 400 billion pairs) didn't finish before the bank closed. Find the best buy/sell pair in a single pass. You can't sell before you buy. The prices are unsigned 64-bit integers, and the file has 10 million of them (204 MB).

Walk through the prices once and remember two things:

  • the lowest price so far, the best moment to have bought, and
  • the best profit so far: the current price minus that lowest price, if it beats the previous best.

The best trade usually isn't "buy at the global minimum, sell at the global maximum", because the maximum may come before the minimum. The organisers noted this was the most common wrong answer.

The prices go up to 2⁶⁴, but a JavaScript number is only exact up to 2⁵³. BigInt would work, but creating 10 million of them is slow, and so is loading 204 MB as one string and splitting it. Instead, the program:

  • reads the file in 16 MB chunks and parses the digits byte by byte,
  • stores each price as two exact numbers, hi · 10¹⁰ + lo,
  • compares and subtracts those pairs directly.

It handles all 10 million prices in about 4 seconds.

The input is too big for git. npm run fetch downloads it from the CoderGames site.

// CoderGames 2020, task 4: best single buy and sell in one pass over 10 million prices.
// Prices are unsigned 64-bit, more than a JavaScript number holds exactly, so each price is
// kept as two exact parts: value = hi * 1e10 + lo. Comparing and subtracting the pairs avoids
// creating 10 million BigInts; the file is streamed in chunks so it is never one big string.
import { openSync, readSync, closeSync } from 'node:fs'

const BASE = 1e10
type Pair = [hi: number, lo: number]
const less = (a: Pair, b: Pair) => a[0] < b[0] || (a[0] === b[0] && a[1] < b[1])
const minus = (a: Pair, b: Pair): Pair => {
  let hi = a[0] - b[0]
  let lo = a[1] - b[1]
  if (lo < 0) {
    lo += BASE
    hi -= 1
  }
  return [hi, lo]
}
const show = (p: Pair) => (BigInt(p[0]) * BigInt(BASE) + BigInt(p[1])).toString()

interface Trade {
  buy: Pair
  sell: Pair
  profit: Pair
}
let lowest = null as Pair | null // cheapest price seen so far
let best = null as Trade | null

function price(p: Pair) {
  if (lowest === null || less(p, lowest)) {
    lowest = p
    return
  }
  const profit = minus(p, lowest)
  if (best === null || less(best.profit, profit)) best = { buy: lowest, sell: p, profit }
}

const fd = openSync(process.argv[2] ?? 'input.txt', 'r')
const buf = Buffer.alloc(1 << 24)
let hi = 0
let lo = 0
let digits = 0
for (let n; (n = readSync(fd, buf, 0, buf.length, null)) > 0; ) {
  for (let i = 0; i < n; i++) {
    const c = buf[i]!
    if (c >= 48 && c <= 57) {
      const l = lo * 10 + (c - 48) // below 1e11, still exact
      hi = hi * 10 + Math.floor(l / BASE)
      lo = l % BASE
      digits++
    } else if (digits) {
      price([hi, lo])
      hi = lo = digits = 0
    }
  }
}
if (digits) price([hi, lo])
closeSync(fd)

if (best === null) console.log('No profitable trade')
else console.log(`Buy: ${show(best.buy)}\nSell: ${show(best.sell)}`)

Two bottles, a thousand floors

Details

A new 1000-storey dormitory opens in Košice. Two students want to find the lowest floor from which their (very sturdy) bottle breaks, and they only have two bottles. What strategy needs the fewest drops in the worst case, and how many drops is that?

This is the classic two-egg problem.

  • With one bottle you have no choice: go up one floor at a time.
  • With two, use the first bottle to narrow the range quickly and the second one to finish floor by floor. If the first bottle breaks after k drops, the second one must cover the gap below, so each gap must be one floor smaller than the previous one. That way the total number of drops stays the same, however far up you get.

So if the worst case is d drops, the first bottle goes to floor d, then d + (d−1), then + (d−2), and so on. Together these steps cover d(d+1)/2 floors. The smallest d with d(d+1)/2 ≥ 1000 is 45 (45·46/2 = 1035).

Halving the range (first drop at floor 500) is a trap: if the bottle breaks, the second bottle has to try floors 1 to 499 one by one. According to the organisers, that was the most common answer.

solution.ts uses the general recurrence. With b bottles and d drops you can cover

reach(b, d) = reach(b−1, d−1) + 1 + reach(b, d−1)

floors: the first drop either breaks the bottle (one bottle fewer for the floors below) or doesn't (the same bottles for the floors above). The program finds the smallest d with reach(2, d) ≥ 1000 and prints where the first bottle is dropped.

45 drops, with the first bottle dropped from floors 45, 89, 132, 174, 215, 255, … 980, 990, 999. When it breaks, go back to the last safe floor and continue one floor at a time with the second bottle.

solution.ts · 24 lines of TypeScript. It reads the input file and prints the answer.

// CoderGames 2020, task 5: lowest floor of a 1000-floor building from which a bottle breaks,
// with only two bottles, in as few drops as possible in the worst case.
//
// With b bottles and d drops you can cover reach(b, d) floors: drop once, and either the bottle
// breaks (b - 1 bottles, d - 1 drops for the floors below) or it doesn't (b bottles, d - 1 drops
// for the floors above). So reach(b, d) = reach(b - 1, d - 1) + 1 + reach(b, d - 1).
const FLOORS = 1000
const BOTTLES = 2

const reach = (b: number, d: number): number => (b === 0 || d === 0 ? 0 : reach(b - 1, d - 1) + 1 + reach(b, d - 1))

let drops = 0
while (reach(BOTTLES, drops) < FLOORS) drops++

// The first bottle goes up in steps of drops, drops - 1, drops - 2, ... so that whenever it breaks,
// the second bottle can walk the floors in between, one by one, within the same total.
const floors: number[] = []
for (let floor = 0, left = drops; left > 0 && floor + left <= FLOORS; left--) {
  floor += left
  floors.push(floor)
}

console.log(drops)
console.log(floors.join(', '))
